## .blend：一个文件装下整个世界

Blender 的项目文件是 `.blend` 格式——模型、材质、动画、渲染设置、场景、甚至 Python 脚本都保存在这一个文件里，**体积小、可整体分发**。这也意味着：

- 打开别人的 `.blend`，等于打开了一个完整的“虚拟制片现场”；
- 外部引用的图像/声音不会自动内嵌——需要分发时执行“打包”即可（见下文）；几何与材质等数据则始终在文件内；
- 合作时注意版本兼容：新版打开旧文件没问题，旧版打开新文件可能丢失新特性。

## 理解数据块（Data-Block）

Blender 内部一切皆**数据块**：网格、材质、图像、动作、世界、灯光、相机……每个数据块在**大纲视图**中都有自己的条目。几个关键特性：

- **复用（Sharing）**：多个物体可以引用**同一份网格数据**。复制物体时若用 `Alt + D`（关联复制）而非 `D`，两个“物体”共享网格——改其中一个的网格，另一个同步更新，省内存且方便批量修改；
- **引用计数与假用户（Fake User）**：没被任何地方引用的数据块在关闭文件时会丢失。想保留又不想被引用？给它一个“假用户”；
- **大纲视图就是数据块的关系图**：看懂它，就理解了 Blender 80% 的数据管理。

## 链接与追加：团队协作的基石

**File（文件）菜单 → Link（链接）/ Append（追加）** 用于把其他 `.blend` 里的数据拿过来：

| 操作 | 行为 | 场景 |
| --- | --- | --- |
| **追加（Append）** | 把数据**复制**进当前文件，之后与源文件无关 | 复用一次性素材 |
| **链接（Link）** | 建立**只读引用**，源文件更新则当前文件跟随更新 | 多人/多场景协作，改资产库一次全生效 |

链接的数据默认不可编辑；若需要“在链接基础上修改”，可使用**库覆盖（Library Override）**——局部覆盖某个链接物体的属性或层级。大型项目常用“主文件 + 若干链接资产文件”的结构，配合下文资产浏览器。

## 集合（Collection）与场景（Scene）

- **集合**是组织物体的容器（旧版叫图层）。集合可以嵌套、设为实例（把整个集合当一个物体摆放）、控制视口/渲染可见性；
- 一个 `.blend` 可含**多个场景**（Scene），每个场景有自己的一套物体/相机/时间线；渲染时选中的是“当前场景”；
- 团队里常见做法：背景道具、角色、灯光各放一个集合，按需开关可见性。

## 资产浏览器（Asset Browser）

把常用内容变成“资产”：

1. 在**大纲/属性**里选中物体或数据块；
2. `Ctrl + Shift + C`（或拖入资产浏览器）标记为资产；
3. 在**资产浏览器**里为它命名、加描述，必要时打包成**资产库（Asset Library）**——一个由文件/目录组成的素材集合；
4. 之后从任意项目拖入即用；属性也可存为**资产（如材质、修改器预设）**。

在**偏好设置 → 文件路径 → 资产库**里可以添加自己的素材目录（本地或共享盘）。Blender 5.2 起还引入了**在线资产库**功能，可以浏览线上资产目录并一键下载到本地。

## 外部数据与文件管理

- **打包（Pack）**：文件菜单 → 外部数据 → **打包全部资源**，把贴图/音频收进 `.blend`，分发更安全；
- **未打包**：反之导出资源，便于版本管理；
- **自动保存与版本**：Blender 默认开启自动保存（`Edit → Preferences → Save & Load`）；保存时可在文件名后追加 `_v02` 之类的版本号；
- **备份习惯**：`.blend` 一旦损坏难修复，重要项目多用版本控制或定期另存。
